# Skill: read

> **元组**：rule `readme-context-guard.md`（always-on触发）+ skill `read`（本文件，操作流程）+ skill `read-sync`（创建/维护认知地图）
> **定位**：按三层架构加载必要认知。用户调用此skill时，AI从README.md的分类法索引出发，找到合适的看法文件，加载看法文件，再从看法文件中找到需要加载的具体文档/代码，逐步深入，只加载完成当前任务所必需的认知。

## 核心问题

**我们无法将整个项目的所有知识都放入AI的上下文。**

一个项目可能有数十个文档、上百个代码文件、数据库、数据资产。全部加载会撑爆上下文窗口，而且大部分内容和当前任务无关。

**三层架构解决这个问题**：通过三层拆分，让AI只加载必要认知去完成一个具体任务。

```
第一层 README.md（分类法索引）——"有哪些视角可以看这个项目"
  ↓ AI判断：当前问题需要哪种视角？
第二层 看法文件（文档索引）——"这个视角下有哪些文档/代码/资产"
  ↓ AI判断：需要加载哪些具体文件？
第三层 具体文档/代码/资产——实际内容
  ↓ AI加载并工作
```

## 什么时候被调用

- 用户说"read"时（后面可能跟上提问内容）
- 用户说"读readme"/"加载readme"/"检查readme"时
- rule `readme-context-guard.md` 触发时（AI回答问题前发现上下文中没有README.md）
- 任何需要了解项目认知才能回答的问题前

## 操作流程

### 步骤1：检查README.md是否在上下文中

检查当前session的上下文中是否已经完整加载了repo根目录的`README.md`。

**判断方法**：
- 如果你能回忆起README.md中的分类法索引（每个分类法的名称、视角、看法文件路径），说明它在上下文中
- 如果你不确定，或者上下文可能已经被压缩，视为"不在上下文中"

### 步骤2：如果不在上下文中，完整加载

用read工具完整加载repo根目录的`README.md`。

**注意**：必须完整加载，不能只读一部分。README.md是分类法索引，缺少任何一个分类法条目都可能导致AI遗漏需要的视角。

### 步骤3：分析用户提问，判断需要哪种视角

读完README.md后，分析用户的提问内容和当前上下文：

1. **这个问题从什么视角看最有意义？** ——对照README.md中的分类法索引，逐个判断每个分类法的视角是否匹配当前问题

2. **是否需要多个视角？** ——有些问题涉及多个视角。如"运行Pipe 4续传并排查stall问题"既需要"运行操作分类法"（怎么运行/检查），也需要"源码分类法"（continuation_control.py怎么实现的），还可能需要"设计决策分类法"（为什么这样设计续传机制）

3. **是否需要查看映射数据库？** ——如果用户的问题涉及某个具体文件/代码变更，可以用 `python3 scripts/view_index.py query-by-asset <path>` 查出这个文件被哪些看法文件索引，从而知道需要加载哪些看法文件

### 步骤4：加载对应的看法文件

用read工具加载步骤3中判断出的分类法对应的看法文件。可以并行加载多个看法文件。

**看法文件是索引，不是内容**——加载看法文件后，你看到的是"这个视角下有哪些文档/代码/资产，它们分别讲什么"，而不是文档的具体内容。

### 步骤5：从看法文件中找到需要加载的具体文档/代码

读完看法文件后，思考：

1. **这个视角下，哪些文档/代码和当前问题相关？** ——对照看法文件中每个条目的"覆盖问题场景"描述

2. **是否有依赖关系需要追加加载？** ——对照看法文件中每个条目的"依赖关系"描述，加载A后可能还需要加载B

3. **是否需要跨视角加载？** ——如果步骤3判断了多个视角，每个视角的看法文件都可能指向需要加载的文档。有些文档可能被多个看法文件索引（视图重叠），只需加载一次

4. **是否需要回到README.md加载其他看法文件？** ——在加载具体文档的过程中，可能发现当前视角不够，需要其他视角的认知。回到README.md，找到其他分类法，加载其看法文件，再从中找到需要的文档

### 步骤6：加载具体文档/代码/资产

用read工具加载步骤5中判断出的相关文档/代码。可以并行加载多个文件。

**按需加载，不要贪多**——只加载和当前任务直接相关的文件。如果加载过程中发现需要更多，再追加加载。

### 步骤7：综合思考，回答/解决用户的问题

带着README.md的分类法认知 + 已加载的看法文件索引认知 + 已加载的具体文档内容认知，综合思考如何回答用户的问题或解决用户的任务。

**关键约束**：不要在认知加载不充分的情况下就回答问题。如果回答过程中发现需要更多文档，停下来加载，再继续。

## 工作流示例

**用户提问**："Pipe 4续传stall了，怎么排查？"

```
步骤1-2：加载README.md
  → 看到分类法索引：系统认知/设计决策/需求/源码/工作流/运行操作/历史

步骤3：分析提问
  → "排查stall"属于"运行操作分类法"（怎么运行/监控/调试）
  → 可能还需要"源码分类法"（continuation_control.py怎么实现的）
  → 可能还需要"设计决策分类法"（为什么这样设计续传机制）

步骤4：加载看法文件
  → 加载 docs/specs/README.md（运行操作分类法）
  → 加载 src/README.md（源码分类法）

步骤5：从看法文件中找具体文档
  → 运行操作看法文件中：AnalysisSystemOps.md（问题排查）、p27_monitor_spec.md（续传检查规范）、continuation_watchdog.sh（看门狗）、continuation_control.py（控制命令）
  → 源码看法文件中：continuation_control.py、continuation_collector.py、continuation_feeder.py、monitor_continuation.py
  → 依赖关系：operational-concerns.md（运维关注点，含stall分析）

步骤6：加载具体文档
  → 加载 docs/system/AnalysisSystemOps.md（问题排查章节）
  → 加载 docs/architecture/operational-concerns.md（stall分析）
  → 加载 monitoring/continuation_control.py（看控制命令实现）
  → 加载 docs/specs/p27_monitor_spec.md（续传检查规范）

步骤7：综合思考
  → 基于排查SOP + stall分析 + 控制命令 + 检查规范，给出排查方案
```

## 关键约束

1. **README.md是起点，不是终点**——README.md只告诉你"有哪些视角"，不告诉你"具体文档讲什么"。必须深入到看法文件，再深入到具体文档
2. **看法文件是索引，不是内容**——看法文件告诉你"这个视角下有哪些文档"，不告诉你"文档的具体内容"。必须加载具体文档才能工作
3. **按需加载，不要贪多**——只加载和当前任务直接相关的文件。三层架构的意义就是"只加载必要认知"
4. **可以回溯**——在加载具体文档的过程中，可能发现需要其他视角的认知。回到README.md，加载其他看法文件，再深入
5. **映射数据库是辅助工具**——当知道某个文件路径但不知道它属于哪些视角时，用 `query-by-asset` 查询；当想确认某个看法文件索引了哪些文件时，用 `query-by-view` 查询

## 工作模式（使用read skill时）

```
1. 系统注入AGENTS.md（铁律+最小索引，always-on）
2. AI用read加载README.md（分类法索引）
3. AI分析用户提问，判断需要哪种视角（分类法）
4. AI加载对应的看法文件（文档索引）
5. AI从看法文件中找到需要加载的具体文档/代码
6. AI加载具体文档/代码/资产
7. 带着必要认知工作（只加载了和当前任务直接相关的认知）
```

## 维护模式（使用read-sync skill时）

```
1. repo文档/代码体系发生变化（新增/修改/删除/重组）
2. 调用read-sync skill
3. 执行分类法决策树（更新既有看法文件 or 新建分类法）
4. 同步映射数据库（view-index.db）
5. 验证三层架构完整性+映射数据库一致性
6. commit
```

## 核心约束（元组级，always-on）

1. **三层架构**——AGENTS.md（铁律）→ README.md（分类法索引）→ 看法文件（文档索引）→ 具体文档/代码。README.md只索引分类法，看法文件才描述具体文档。
2. **我们无法将整个项目的所有知识都放入AI上下文**——三层架构的意义是让AI只加载必要认知去完成具体任务。
3. **必须完整加载README.md**——不能只读一部分。缺少任何一个分类法条目都可能导致AI遗漏需要的视角。
4. **看法文件是索引，不是内容**——加载看法文件后还要加载它指向的具体文档才能工作。
5. **维护责任**——文档/代码变更时，必须用`read-sync` skill同步更新看法文件和映射数据库。
